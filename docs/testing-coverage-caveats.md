# Testing: Code Coverage Caveats

This document describes known limitations of coverage tools (Istanbul, V8) in the context of Angular + Vitest tests. Most of them come from the gap between the code produced by AOT compilation and what coverage tools can map back to the source: dev-mode metadata that is only evaluated during JIT recompilation, and defensive branches generated by the compiler.

Unlike ADRs, this document is a living reference: update it whenever a caveat disappears or a new one is found.

## 1. Uncovered `forwardRef` closure in `viewChild()` with a type token

**Observed with:** Angular `22.1.8`, Vitest `4.1.11`. Compiled output verified with Angular `22.3.0`.

**Problem**

For a signal query with a type token, e.g. `viewChild.required(CdkListbox)`, the AOT compiler emits the token in two places:

- in the component definition (`ɵcmp.viewQuery`), which is used at runtime:
  `ɵɵviewQuerySignal(ctx.listbox, CdkListbox, 5)`
- in the dev-mode class metadata (`ɵsetClassMetadata`), wrapped in a closure:
  `{ type: ViewChild, args: [forwardRef(() => CdkListbox), { isSignal: true }] }`

The closure `() => CdkListbox` is only called when this metadata is read, which happens when `TestBed` recompiles the component in JIT mode (`overrideComponent` / `overrideTemplate`). Regular AOT tests never call it, so Istanbul reports the closure as an uncovered function (`fstat-no`), even though the query itself is fully tested.

**Workaround**

A dedicated isolated test calls `TestBed.overrideTemplate` on the component, which makes `TestBed` read its metadata and resolve the `forwardRef`. The test itself does not count towards template coverage, as it runs against the JIT-recompiled definition (see section 3). This does not matter here: the closure lives in the original, instrumented class metadata, so calling it is recorded, while the template is covered by the standard AOT tests.

## 2. Fallback branch in two-way bindings on Signals (`[(x)]="y"`)

**Observed with:** Angular `22.1.8`, Vitest `4.1.11`. Compiled output verified with Angular `22.3.0`.

**Problem**

The compiler generates the following listener for a two-way binding:

`ɵɵtwoWayBindingSet(ctx.y, $event) || (ctx.y = $event)`

`ɵɵtwoWayBindingSet` writes to the target and returns `true` if it is a `WritableSignal`; otherwise it returns `false` and the plain property assignment runs. When `y` is always a signal (`signal()` / `model()`), the right-hand side of `||` is never executed, and coverage tools report it as an uncovered branch.

**Workaround**

None. The branch cannot be covered without replacing the signal with a plain property. It is safe to ignore.

See [0007. Real Child Components in Component Tests](./adr/0007-real-child-components-in-component-tests.md). This case is documented as an ADR because it led to a project-wide testing decision rather than a targeted workaround.

## When to Review

Review this document whenever Angular, Vitest or the coverage provider gets a major version upgrade. For each case, check whether the compiled output or the coverage report still shows the problem, and remove the case if it does not.
